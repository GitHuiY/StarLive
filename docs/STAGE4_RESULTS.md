
该入口运行计划核心测试、本机 Android 测试、debug APK 构建和 Android Lint。构建工具及固定版本见 [BUILD.md](BUILD.md)。本机界面测试使用 Robolectric 4.15.1／API 35／原生绘图，中文、一般页面为 360×800 dp，与目标手机的逻辑尺寸相近，另测 1.6 倍字体。它不能证明 vivo 系统外观、触摸、权限或后台行为已通过。

初次电脑模拟器尝试未通过：硬件加速未就绪，软件模式启动后首次 ADB 检查返回 `device offline`。已报告并关闭本轮自有模拟器进程；没有执行重连、重启 ADB 服务、改 Windows 系统功能或重启电脑。随后改用本机 Android 测试。

初次本机截图使用的 PixelCopy 路径超时，已改为绘制实际窗口内容。本机检查曾发现默认标题黑色在深色背景下对比不足，已统一默认内容色并通过新截图复核。数据与 UI 复核中还修复了旧设置快照覆盖、快速排序丢动作、跨周弹窗目标漂移、长标题编辑限制、备份预览缺设置、恢复失败丢目标及提交结果不明时错误继续写入等问题。

本机检查有以下环境适配，均不进入 APK：

- 含输入框的三个弹窗用例使用 320 dp 宽度，规避 [Robolectric 已知的指定宽度下弹窗反复布局问题 #8460](https://github.com/robolectric/robolectric/issues/8460)；其余界面仍使用 360 dp。弹窗文字通过实际控件的 SetText 入口更新，仍检查保存、确认和持久化，但未验证真实输入法。
- Windows 上实证 `File.renameTo` 无法覆盖已有文件，而 [Android AtomicFile 的提交代码依赖原子替换的 rename 语义](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/core/java/android/util/AtomicFile.java)。测试 shadow 仅把该私有平台调用映射为 `Files.move(ATOMIC_MOVE, REPLACE_EXISTING)`；真实文件流、同步、读回校验与存储队列继续执行。生产 Android 保存逻辑未为宿主系统降级。
- 每个界面用例重置宿主生命周期工厂的静态 Application 缓存，并在关闭前等待 IO 队列屏障，防止前一用例假数据或待完成写入混入下一用例；保留首次个人数据为空及目录一致性断言。

Lint 曾读取生成路径文件的错误转义；构建脚本已修正，刷新分析后最终通过。该修正没有改变 SDK 安装、依赖检查规则或产品功能。
